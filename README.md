# Multimodal Deepfake Detector ("Clipcheck")

**CM3070 Final Year Project, University of London (BSc Computer Science). Template: "Orchestrating AI Models to Achieve a Goal".**

A system that takes one video clip and answers three questions: is it manipulated, which part (the face or the voice) is implicated when
the two disagree, and why, in plain language a non-expert can act on. Research question: *can cross-modal inconsistency between facial
video and speech signals improve deepfake detection compared with single-modality detection?* The contribution is what the system
reports: a large gap between the two per-modality scores becomes a distinct "partly manipulated" verdict (`PARTIAL_MANIPULATION`) that
names the implicated part, instead of being averaged away into one label.

```
video -> MTCNN face crops -> Xception -> P(video_fake) --------+
                                                               +-> disagreement check (T = 0.35) -> accuracy-weighted fusion,
audio -> Silero VAD -> wav2vec2 (frozen) -> RBF SVM -> P(audio_fake) +   or PARTIAL_MANIPULATION naming the higher part
                                                                                  |
         out-of-domain check per branch (warning only)  --------------------------+-> Llama 3 8B explanation (constrained),
                                                                                      checked; plain-language template fallback
```

> **Research prototype, not a forensic tool.** It gives likelihoods, never proof, and states its own limits next to every result.

The project's governing rule: **no number is reported unless a file in this repository shows the code that produced it.** Figures below
come from `results/numbers.md` (generated by `scripts/build_numbers.py`), the ledger `docs/EXPERIMENTS.md`, or the result file named
beside them; if this page and those files ever differ, the files win. `results/README.md` says which result folders are current.

## What was built and what was measured

| Stage | Model | Status |
|---|---|---|
| Face detection | MTCNN (facenet-pytorch), 224 x 224 crops | built |
| Video classifier | Xception (timm `legacy_xception`), fine-tuned on FaceForensics++ c23, three methods (Deepfakes, FaceSwap, NeuralTextures), seed 44 | chosen by a five-backbone comparison against a rule fixed in advance; the PPR's EfficientNet-B4 was tested twice and failed it |
| Speech detection | Silero VAD | built |
| Audio | wav2vec2-base (frozen) + RBF SVM trained on ASVspoof 2019 LA | eval EER 3.96%, balanced accuracy 95.7% |
| Fusion | disagreement threshold T = 0.35 (tuned on held-out data), weights video 0.46 / audio 0.54 (from video cross-validated accuracy 82.8% and audio balanced accuracy 95.7%) | built and evaluated |
| Out-of-domain check | Mahalanobis distance per branch | shipped as a WARNING (withholding scores failed its own pre-set rule) |
| Explanation | Llama 3 8B via Ollama, constrained prompt; automatic faithfulness screen; plain-language template when the screen rejects the text | Llama 3 kept after a comparison with Mistral 7B and Qwen 2.5 7B (ledger M1); rated by two raters (ledger E2) |
| Web app ("Clipcheck") | FastAPI + vanilla HTML/CSS/JS | final interface (v4) frozen on 27 Sep 2026; v1 and v2, the two user-tested versions, are kept and runnable |

### Key results

1. **Core result (ledger F5, held-out video, self-built set, n = 76).** Video only 92.5%, audio only 92.1%, standard fusion 76.3%,
   **disagreement-aware fusion 94.7%: +18.4 points over standard fusion (95% CI +7.9 to +28.9)**. It names the voice correctly on 100% of
   real-video/fake-voice clips and the video on 75% of fake-video/real-voice clips.
2. **The boundary, stated beside the headline.** On a different dataset (DeepfakeTIMIT) it names the video correctly on **0%** of
   fake-video/genuine-voice clips (ledger H2), and on the independent LAV-DF set both branches are at or below chance (video AUC 0.377, audio
   AUC 0.522; ledger F6). The mechanism works while both branches see data like their training data.
3. **An evaluation bug was found and fixed.** The original frame-level split put every test video's frames in training too. The same
   EfficientNet-B4 scored 97.67% frame accuracy on it and 89.93% on the corrected identity-disjoint split (`data_splits/`, guarded in CI).
4. **Model choice by measurement.** On the corrected split EfficientNet-B4 was the weakest of five backbones; single-method models detected
   0% of FaceSwap fakes; three-method training fixed that. B4 retrained on three methods, plain and with the PPR's regularisation, failed a
   ship rule written before its runs (mean validation accuracy 74.5% and 69.9% against 84.3% required). Xception shipped over ConvNeXt-Tiny
   for its lower false-alarm rate (3.0% against 9.1% of genuine videos). Full record: `docs/decisions/video_backbone_decision.md`.
5. **Honest accuracy of the shipped video model: about 83%** (5-fold cross-validation over 400 videos, 95% CI 79.2% to 86.2%); 59.1% on
   Celeb-DF-v2 zero-shot.
6. **Audio.** wav2vec2 beats MFCC (EER 3.96% against 10.25%) and WavLM was not better; but genuine speech from an unseen corpus is flagged as
   spoof (100 of 100 clips), a training-corpus gap, not a codec or encoder problem (ledger A5, A6, F7).
7. **Explanations (ledger E2).** Two raters scored 50 explanations (quadratic-weighted kappa 0.63, 0.81 and 0.93 on the three criteria); every
   one of the 15 texts both raters faulted had also been rejected by the app's automatic screen. Only one rater is independent of the project.
8. **Latency** (ledger L3, Apple M2 Pro): 7.3 s per clip warm, all stages; 1.3 to 8.0 s end to end in the app (median 4.4 s).
9. **User testing** (`docs/user_testing/`): round 1 (v1) found information overload and a warning that testers missed; the interface was
   redesigned from those findings, a heuristic review and a designer's mockups (`docs/user_testing/findings.md`). Round 2 (v2, the same four
   people): SUS median 88.75 against 60, but the warning no longer lowered trust in a wrong verdict (0 of 4). Round 1 data is provisional
   (a survey-form defect, `docs/user_testing/results/round1_data_quality.md`). The final interface (v4) acts on round 2's lessons, for
   example by putting the warning inside the verdict, but has not been user-tested.

### Known limitations

- **Not FakeAVCeleb**: it never arrived, so the four-condition sets are self-built (FaceForensics++ video muxed with ASVspoof speech); only
  22 real test videos exist, so the two real-video categories share videos.
- **Cross-dataset**: 59.1% on Celeb-DF-v2; chance on LAV-DF. The out-of-domain warning flags all 50 wrong LAV-DF verdicts, but it flags 199 of
  the 200 LAV-DF clips, and most Celeb-DF errors go unflagged.
- **Three FaceForensics++ methods only**; nothing supports claims about other generators or fully synthetic faces.
- **Single-corpus audio**: a genuine voice recorded elsewhere may be called synthetic.
- **Clip-level design**: LAV-DF-style fakes that last a fraction of a second are diluted by averaging.
- **Explanations**: the AI-written text still uses technical words when it passes its check; the automatic screen is keyword based.
- **Small user testing**: the same four people in both rounds; the final interface is untested.
- No lip-sync signal: the "inconsistency" is disagreement between two per-part scores.

## Repository layout

```
server.py, static/          FastAPI backend and the Clipcheck interface (final, v4)
run_server.sh               start the app (port 8000)
run_v1_interface.sh         the frozen v1 interface on port 8001; run_v2_interface.sh: frozen v2 on port 8002 (same backend)
scripts/                    the app's pipeline modules, plus training, evaluation and study scripts; scripts/README.md indexes every file
scripts/launchers/          the one-off overnight job queues that produced the experiments
tests/                      unit, integration and data-invariant tests (207 in 19 suites)
models/                     shipped_model.json and the model card (README.md); weights are release assets, not in git
data_splits/                frozen identity-disjoint split and CV folds (SHA-256)
eval_*/manifest.json        the four evaluation sets: every clip's source files (the clips themselves are not in git)
results/                    result folders and numbers.md / numbers.json (generated); results/README.md marks current vs superseded
docs/                       EXPERIMENTS.md (ledger), DEV_LOG.md, LESSONS.md, TESTING_GUIDE.md, decisions/, user_testing/; docs/README.md indexes them
.github/workflows/ci.yml    CI: compile check + the data-free tests
```

The datasets and everything derived from them are not part of the repository (git-ignored): `data/` (FaceForensics++ videos), `frames/`,
`frames_methods/`, `frames_multi/` (face crops), `external_datasets/` (DeepfakeTIMIT, LAV-DF), the evaluation clips, and the training
checkpoints in `models/runs/`. The training and evaluation scripts expect them at these paths. The app does not need them: it loads only the
code, `static/`, the files in `models/` and a few result files, and the example clips are optional (see Running the app).

## Setup

Two Python environments are needed because `facenet-pytorch` (MTCNN) and `soundfile` do not coexist cleanly. Running a script in the
wrong one gives an import error, not a wrong answer.

| | `base` | `deepfake-detect` |
|---|---|---|
| Used for | training, evaluation, audio branch, explanation, most tests | the app (`server.py`), face extraction, video inference, the app tests |
| Has MTCNN | no | yes |
| Requirements | `requirements-base.txt` | `requirements-app.txt` |

```bash
python -m pip install -r requirements-base.txt              # in the base environment
python -m pip install -r requirements-app.txt               # in the deepfake-detect environment
brew install ollama && ollama serve && ollama pull llama3:8b   # optional: the AI-written explanation (about 4.7 GB)
```

Paths assume `/opt/anaconda3`; adjust to your environments. Without Ollama the app still works
and shows the plain-language standard wording, labelled as such. Keep scikit-learn at the pinned versions: the voice model was saved with
scikit-learn 1.4.2 (`requirements-base.txt`) and the app loads it under 1.9.0 (`requirements-app.txt`), so a different version could change it.

### Data (not included)

The datasets are **not in this repository** and remain under their own terms. FaceForensics++ in particular may not be redistributed, so
no dataset-derived media (videos, face crops, the example clips) is committed; manifests that name the source files are.

| Dataset | Used for | Get it |
|---|---|---|
| FaceForensics++ c23 (Deepfakes, FaceSwap, NeuralTextures) | video training and evaluation | request access from the authors; `scripts/download_ff.py`, `scripts/download_extra_methods.sh` |
| Celeb-DF-v2 | cross-dataset video test | request from the authors; `scripts/eval_celebdf.py` |
| ASVspoof 2019 LA | audio training and evaluation | public; `scripts/train_audio_svm.py --check-layout` |
| DeepfakeTIMIT | hybrid probe, unseen-corpus speech | public (Zenodo) |
| LAV-DF | independent audio-visual test | Hugging Face; `scripts/carve_lavdf_parts.py`, `scripts/build_lavdf_eval_set.py` |

## Running the app

```bash
./run_server.sh              # http://localhost:8000 ; add #testing to the address for neutral example names (user testing)
./run_v1_interface.sh        # the original interface, http://localhost:8001 (same backend)
./run_v2_interface.sh        # interface v2, the version round 2 of user testing used, http://localhost:8002
```

`server.py` drives the same inference code as the scripts (`video_infer.py`, `audio_branch.py`, `vad.py`, `fusion.py`, `ood_gate.py`,
`explain.py`, `explain_checks.py`); models, thresholds and fusion logic never live in the server. Example clips appear when the local,
git-ignored `demo_videos/`, `eval_fallback/` and `eval_lavdf/` folders are present.

### Demo videos (rebuild locally)

The eight demo videos on the Check a video page are built from FaceForensics++ video and ASVspoof 2019 speech, so they are not in this
repository; a fresh copy shows a short note in their place. To rebuild them, get the datasets (table above), then run
`python scripts/build_fallback_eval_set.py` (writes `eval_fallback/`, the source of all eight; every clip's source files are listed in
`eval_fallback/manifest.json`) and, for the LAV-DF clips used in testing mode, `python scripts/build_lavdf_eval_set.py`. The no-face test pattern
is made with the one-line ffmpeg recipe in `docs/TESTING_GUIDE.md` section 8. Restart the server and the demo row appears.

## Reproducing the results

```bash
python scripts/freeze_split.py                              # freeze the identity-disjoint split (SHA-256)
python scripts/build_multimethod_frames.py                  # balanced three-method training folder (symlinks)
scripts/run_cell.sh mm_xcep_vidsplit 44 --arch legacy_xception --frames-dir frames_multi --epochs 10   # one train + evaluate cell
python scripts/aggregate_runs.py --tag mm_xcep_vidsplit     # mean and std over seeds
python scripts/eval_cross_method.py --tags mm_xcep_vidsplit # per-method detection on unseen identities
/opt/anaconda3/envs/deepfake-detect/bin/python scripts/eval_fallback_4condition.py --manifest eval_heldout/manifest.json --out-dir results/repro_check/heldout
python scripts/bootstrap_fusion_advantage.py --results results/repro_check/heldout/fallback_4condition_results.json --out results/repro_check/heldout/advantage_bootstrap.json
/opt/anaconda3/envs/deepfake-detect/bin/python scripts/benchmark_latency.py --out results/repro_check/latency.json
python scripts/build_numbers.py                             # regenerate results/numbers.md and numbers.json
```

`docs/TESTING_GUIDE.md` lists what to expect from each command and from each example clip in the app. `docs/EXPERIMENTS.md` is the ledger
of every run, including superseded ones; `docs/LESSONS.md` records what went wrong and the rule that follows.

## Tests

```bash
python -m pytest -q --ignore=tests/test_pipeline.py --ignore=tests/test_server.py                         # base env: 142 pass, 11 skipped
/opt/anaconda3/envs/deepfake-detect/bin/python -m pytest -q tests/test_server.py tests/test_pipeline.py   # app env: 28 pass, 24 skipped
```

Counts as of 28 Sep 2026 (207 tests in 19 suites), without the datasets, as in a fresh clone: eight tests in `test_data_split.py` need the
FaceForensics++ face crops (`frames/`, `frames_multi/`), and the tests that run the demo clips (`demo_videos/` and the example clips in
`eval_fallback/`, `eval_lavdf/`) need those clips; all of them skip when their data is absent. With the data present: base 152 pass,
1 skipped; app 54 pass. CI runs the data-free subset (88 pass, 1 skipped) with `DEEPFAKE_SKIP_HEAVY=1`. The
tests check that the implementation matches its specification (leakage guarantees, fusion logic, the explanation screen, plain-language
wording, the interface's data, the frozen interfaces), not that a detection result is good. Suites needing an optional service (Ollama,
Silero VAD) skip cleanly when it is absent.
